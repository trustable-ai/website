# Trustable CRM

A demo CRM: customer contacts on one side, support tickets on the other, and a
chat window where you can ask about either in plain language.

It's a showcase for the Trustable platform, so it runs entirely on generated
demo data — no external systems are connected, and nothing you change survives a
redeployment.

## Dashboard

Six counters open the app: total contacts, active contacts, open tickets,
in-progress, closed, and high-priority. Below them, quick links into Contacts,
Tickets and the chat.

## Contacts

The full contact list, each with name, email, company, phone and an active or
inactive badge. Search by name, email or company — it filters as you type — and
narrow by status. Results are paginated.

Opening a contact shows their details in full. The activity area on that page is
still a placeholder: it says as much, and the Send Email, Call and Add Note
buttons beside it are not wired up yet.

## Tickets

Every support ticket, newest activity first, filterable by **status** (open,
in-progress, closed), **priority** (low, medium, high, critical) and **type**
(support, billing, technical, feature request, complaint), with paging.

Select a ticket to see it in detail: its title and description, the contact who
raised it, its badges, and a **timeline** of everything that has happened to it —
creation, status changes, notes. Change the status from the same panel and the
timeline records the transition, the ticket's updated time moves, and the
dashboard counters recalculate.

## Chat

A conversation window over the same data, with quick-prompt buttons to get you
started. It understands a handful of intents — in Italian, matching the rest of
the interface:

| Ask | And it |
|---|---|
| "quanti contatti" | answers with the contact count |
| "mostra ticket aperti" | opens the open tickets |
| "ultimi ticket" | shows the most recent tickets |
| "chiudi ticket #42" | closes that ticket and logs it on its timeline |
| "cerca Mario" | searches contacts by name |

Some replies come back with an action attached, which navigates the app to the
matching list. Anything it doesn't recognise gets a prompt suggesting what it can
do. This is keyword and pattern matching, not a language model — the phrasings
above are close to what it expects.

## How it is put together

A React and TypeScript single-page app (Vite, Tailwind CSS, shadcn/ui, TanStack
Query), in Italian, talking to Python actions on Apache OpenServerless:

| Endpoint | Does |
|---|---|
| `GET /api/my/v1/dashboard-stats` | the six dashboard counters |
| `GET /api/my/v1/contacts-list` | contacts, with search, status filter and paging |
| `GET /api/my/v1/tickets-list` | tickets, with status, priority and type filters |
| `POST /api/my/v1/tickets-update` | change status or priority, append a note |
| `POST /api/my/v1/chat-query` | interpret a chat message, return a reply and optional action |

**Redis** is the whole data layer — contacts and tickets are stored as keyed JSON
documents, and the dashboard statistics are cached for five minutes and
invalidated whenever a ticket changes.

A private action, `init/load-demo-data`, generates the demo world: 30 contacts
across eight companies and 50 tickets spread over the statuses, each with a
timeline of events. It refuses to run twice, so re-invoking it is safe.

## Getting started

```bash
npm install
npm run dev
```

The backend needs Redis configured. Invoke `init/load-demo-data` once to
populate the CRM, then open the dashboard.
